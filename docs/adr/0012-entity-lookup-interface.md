# 0012 Country/entity lookup behind an interface, no-op in v1
**Status:** Accepted (2026-10-12). **Context:** Several designed features need a callsign-to-entity table (auto-answer policies for country/continent and "new DXCC", per-country map colouring, worked-before by entity). The usual source is cty.dat, maintained by Jim Reisert AD1C. When this ADR was written its licence was unverified, and bundling data of unknown licence into a GPLv3 app is exactly the provenance problem ADR 0001 exists to avoid. **Decision:** Define entity lookup as an interface in `core-log` with a **no-op implementation in v1**. v1 ships only the policies that need no entity table: grid distance and bearing, "new grid", worked-before by callsign, SNR, first heard.

**Amended 2026-10-12, same day: cty.dat is MIT.** The maintainer read country-files.com/copyright/ in a browser and confirmed the standard MIT grant, so the data **may** be bundled in this GPLv3 app provided the copyright and permission notice travel with it. **The decision above is unchanged, but its reason is now different:** entity lookup stays out of v1 because of the ADR 0011 scope cut, not because of licence risk. The licence is no longer a blocker, and the maintainer notes this class of data could also be built from scratch if ever preferred.

**Amended 2026-10-16: the table is in, for the Roster.** The maintainer asked for a country column, sorted alphabetically: "you tend to get all the DX stations that are NOT starting with U 'United States...' at the top." So `EntityLookup` and its cty.dat implementation `CtyDat` now exist in `core-log`, as this ADR planned. The file is bundled unmodified at `app/src/main/assets/cty/cty.dat` (VER20260915), with its notice in `THIRD_PARTY_LICENSES.md`. For now it feeds only the Roster's country column and Country sort. The policy criteria (country, continent, new DXCC) and per-country map colouring are still not built, and each needs asking before it is. Slash calls use a simple rule (drop operating suffixes and area digits, then the shorter part is the prefix); cty.dat's exact-call entries cover the known exceptions.

**Consequences:** The interface boundary remains worth having — it keeps the bundled table swappable for a self-built one and keeps the policy engine testable with no data file. The policy UI must degrade honestly — country/continent/DXCC criteria hidden or disabled rather than silently matching nothing — and the Map must render with no per-country colouring until the table is in. When the table is vendored, reproduce the notice verbatim in `THIRD_PARTY_LICENSES.md`. Alternative sources, if ever needed: ITU prefix allocations or the ADIF DXCC list, both less accurate on portable prefixes and split entities.
