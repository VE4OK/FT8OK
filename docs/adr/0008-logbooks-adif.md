# 0008 Logbooks and ADIF
**Status:** Accepted for auto-save and ADIF-only export; logbook types Proposed. **Decision:** Room database is the source of truth; each logbook has an auto-saved ADIF file in a user-chosen folder (SAF). Logbook types General, POTA, SOTA, Contest. Archive-and-clear requires typing CLEAR after a copy is written to `Documents/FT8/Archive/`. P2P park entry is after the fact only ("Their park?" action, `P2P?` tag).

**Amended 2026-10-12:** the earlier "export both POTA field sets" hedge is **withdrawn**. POTA's own ADIF reference documents `MY_SIG` = `POTA` with `MY_SIG_INFO` = your park, and `SIG`/`SIG_INFO` for park-to-park; it does not mention `POTA_REF`/`MY_POTA_REF` anywhere, and those ADIF fields are not used for interchange with pota.app. **Export `MY_SIG`/`MY_SIG_INFO` and `SIG`/`SIG_INFO` only.** Required per-QSO fields are `STATION_CALLSIGN` or `OPERATOR`, `CALL`, `QSO_DATE`, `TIME_ON`, `BAND`, and `MODE`/`SUBMODE` (POTA stores one MODE; if both are given, SUBMODE wins). `MY_STATE` is recommended. Source: https://docs.pota.app/docs/activator_reference/ADIF_for_POTA_reference.html

**Consequences:** `allowBackup=false`; the ADIF folder is the migration path between phones. Per-park files named `CALL@PARK-yyyymmdd.adi` — POTA's convention is `callsign@park#-yyyymmdd`, a **four-digit year** (e.g. `K1ABC@US-8088-20220202.adi`), and for n-fers one file per park with the same QSOs.
